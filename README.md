# Inline Assembly в Rust: разбор кода с `rdtsc`

## Что такое inline assembly

**Inline assembly** — это возможность вставлять **ассемблерные инструкции прямо в Rust-код** через макрос `asm!`. Компилятор передаёт их ассемблеру как есть, не пытаясь оптимизировать или переупорядочить (если не указано иное).

```rust
core::arch::asm!(
    "инструкция",      // ассемблерный код
    операнды...        // входы/выходы/боковые эффекты
);
```

## Полный разбор кода

```rust
#[cfg(target_arch = "x86_64")]
fn asm_int() -> u64 {
    let lo: u32;   // младшие 32 бита TSC
    let hi: u32;   // старшие 32 бита TSC

    unsafe {
        core::arch::asm!(
            "rdtsc",            // ← инструкция процессора
            out("eax") lo,      // ← выходной операнд: EAX → lo
            out("edx") hi,      // ← выходной операнд: EDX → hi
        );
    }

    (hi as u64) << 32 | lo as u64
}
```

Разберём каждую часть.

---

## 1. Условная компиляция

```rust
#[cfg(target_arch = "x86_64")]
```

Атрибут `#[cfg(...)]` включает функцию **только** при компиляции под x86-64. На ARM, RISC-V и других архитектурах функция просто не существует.

**Зачем**: `rdtsc` — инструкция **только x86/x86-64**. На других архитектурах её нет, и код не соберётся.

---

## 2. Объявление переменных

```rust
let lo: u32;   // младшие 32 бита TSC
let hi: u32;   // старшие 32 бита TSC
```

Обе переменные имеют тип **`u32`** — потому что `EAX` и `EDX` это **32-битные регистры**.

> ⚠️ Переменные **не инициализированы** — их значения будут записаны ассемблером. Rust позволяет это, потому что компилятор видит `out(...)` и знает, что переменные будут заполнены.

---

## 3. Блок `unsafe`

```rust
unsafe {
    core::arch::asm!(...);
}
```

`asm!` **всегда требует `unsafe`**, потому что компилятор не может проверить:
- корректность инструкций,
- совместимость регистров,
- сохранность состояния процессора,
- отсутствие побочных эффектов.

Ответственность за корректность лежит **на программисте**.

---

## 4. Инструкция `rdtsc`

```rust
"rdtsc"
```

**`RDTSC`** расшифровывается как **Read Time-Stamp Counter** — «прочитать счётчик меток времени».

### Что она делает

1. Читает **64-битный TSC** (Time-Stamp Counter) — счётчик тактов процессора с момента включения.
2. **Атомарно** разделяет его на две половины:
   - **младшие 32 бита** → регистр **`EAX`**;
   - **старшие 32 бита** → регистр **`EDX`**.

```
TSC (64 бита):
┌──────────────────────────┬──────────────────────────┐
│    EDX (старшие 32)      │    EAX (младшие 32)      │
└──────────────────────────┴──────────────────────────┘
```

### Особенности инструкции

- **Нет операндов** — работает с фиксированными регистрами `EAX` и `EDX`.
- **Не сериализующая** — процессор может переупорядочить инструкции вокруг неё.
- **Не привилегированная** — доступна из userspace.
- **Атомарная** — обе половины читаются согласованно.

---

## 5. Выходные операнды

```rust
out("eax") lo,   // EAX → lo
out("edx") hi,   // EDX → hi
```

### Синтаксис `out(...)`

| Часть | Значение |
|---|---|
| `out` | **Выходной** операнд — регистр **записывается** инструкцией |
| `"eax"` | Имя регистра (строка — требование синтаксиса) |
| `lo` / `hi` | Rust-переменные, куда попадут значения |

### Что происходит под капотом

1. Rust резервирует регистры `EAX` и `EDX` для этого блока `asm!`.
2. Ассемблер выполняет `rdtsc`, которая **жёстко** пишет в `EAX` и `EDX`.
3. После выполнения Rust копирует `EAX` → `lo`, `EDX` → `hi`.

### Почему именно `EAX` и `EDX`

Потому что **`rdtsc` физически привязана к этим регистрам** — это требование архитектуры x86. Нельзя попросить её писать в `EBX` или `ECX`.

---

## 6. Сборка 64-битного значения

```rust
(hi as u64) << 32 | lo as u64
```

Выполняется в порядке:

```
1. hi as u64           ← u32 → u64
2. lo as u64           ← u32 → u64
3. (hi as u64) << 32   ← сдвиг на 32 бита влево
4. ... | ...           ← побитовое ИЛИ
```

Эквивалентно:

```rust
((hi as u64) << 32) | (lo as u64)
```

**Результат**: 64-битное значение TSC, где:
- старшие 32 бита = `hi` (были в `EDX`);
- младшие 32 бита = `lo` (были в `EAX`).

---

## Регистры подробно

### `EAX`

| Свойство | Значение |
|---|---|
| Полное имя | Extended AX |
| Размер | 32 бита |
| Часть чего | Младшие 32 бита `RAX` (в x86-64) |
| Роль в `rdtsc` | **Младшие 32 бита** TSC |
| Другие роли | Возврат из функций, аккумулятор, syscall |

### `EDX`

| Свойство | Значение |
|---|---|
| Полное имя | Extended DX |
| Размер | 32 бита |
| Часть чего | Младшие 32 бита `RDX` (в x86-64) |
| Роль в `rdtsc` | **Старшие 32 бита** TSC |
| Другие роли | Второй операнд `mul`/`div`, I/O-порт |

### Иерархия регистров

```
RAX (64) ┌──────────────────────────────────┐
         │  EAX (32)                        │
         │  ┌──────────────┬──────────────┐ │
         │  │  AX (16)     │              │ │
         │  │  ┌────┬────┐ │              │ │
         │  │  │ AH │ AL │ │              │ │
         │  │  └────┴────┘ │              │ │
         │  └──────────────┴──────────────┘ │
         └──────────────────────────────────┘
```

Аналогично для `RDX` / `EDX` / `DX` / `DH` / `DL`.

## Что такое intrinsic

**Intrinsic** (встроенная функция) — функция, которую компилятор заменяет на **конкретную инструкцию процессора**.

Примеры:
- `core::arch::x86_64::_mm_add_ps` → `ADDPS` (сложение SSE-векторов);
- `core::arch::x86_64::_rdtsc()` → `RDTSC`;
- `core::arch::x86_64::_mm256_loadu_si256` → `VMOVDQU` (загрузка AVX).

### Ваш код — ручной intrinsic

```rust
core::arch::asm!("rdtsc", out("eax") lo, out("edx") hi)
```

Это **ручная реализация** того, что делает `_rdtsc()`:

```rust
// Эквивалент через intrinsic:
let tsc = unsafe { core::arch::x86_64::_rdtsc() };
```

`_rdtsc()` — обёртка над `rdtsc`, возвращающая `u64` напрямую. Ваш код делает то же самое, но вручную, что полезно для понимания.

---

## Когда использовать inline assembly

| Ситуация | Использовать? |
|---|---|
| Есть intrinsic в `core::arch` | ❌ Используйте intrinsic |
| Есть крейт с нужной функцией | ❌ Используйте крейт |
| Нужна инструкция, которой нет в intrinsic | ✅ `asm!` |
| Нужен точный контроль над регистрами | ✅ `asm!` |
| Оптимизация под конкретную архитектуру | ⚠️ После измерений |
| Прикладной код | ❌ Почти никогда |

**Правило**: `asm!` — **последнее средство**. Сначала попробуйте intrinsic, потом крейт, и только если ничего нет — ассемблер.

---

## Опасности inline assembly

| Опасность | Пояснение |
|---|---|
| **Нет проверок** | Компилятор не поймает ошибку в регистрах/инструкциях |
| **Портируемость** | Код работает только на конкретной архитектуре |
| **Переупорядочивание** | `rdtsc` не сериализующая — нужен `lfence` для точности |
| **Несовместимость с оптимизациями** | Компилятор может не знать о побочных эффектах |
| **Сложность отладки** | Ошибки в ассемблере приводят к UB или падениям |

---

## Улучшение: сериализация через `lfence`

Для точных измерений `rdtsc` нужно «обезопасить» от переупорядочивания:

```rust
unsafe {
    core::arch::asm!(
        "lfence",           // сериализация — ждём завершения всех инструкций
        "rdtsc",
        out("eax") lo,
        out("edx") hi,
        options(nostack, preserves_flags),
    );
}
```

Или использовать `rdtscp` — она **сама** сериализующая:

```rust
unsafe {
    core::arch::asm!(
        "rdtscp",
        out("eax") lo,
        out("edx") hi,
        out("ecx") _aux,    // rdtscp также пишет в ECX (ID ядра)
        options(nostack, preserves_flags),
    );
}
```

## Итог

| Элемент | Что делает |
|---|---|
| `#[cfg(target_arch = "x86_64")]` | Компилирует только под x86-64 |
| `let lo: u32; let hi: u32;` | Переменные для половин TSC |
| `unsafe { ... }` | Ассемблер требует `unsafe` |
| `core::arch::asm!` | Макрос inline assembly |
| `"rdtsc"` | Инструкция: читает TSC в `EAX` и `EDX` |
| `out("eax") lo` | `EAX` → `lo` (младшие 32 бита) |
| `out("edx") hi` | `EDX` → `hi` (старшие 32 бита) |
| `(hi as u64) << 32 \| lo as u64` | Сборка 64-битного значения |

**Одной фразой**: код вручную реализует intrinsic `_rdtsc()` через inline assembly — инструкция `RDTSC` читает 64-битный счётчик тактов процессора в регистры `EAX` (младшие 32 бита) и `EDX` (старшие 32 бита), которые затем собираются в одно `u64`-значение.
